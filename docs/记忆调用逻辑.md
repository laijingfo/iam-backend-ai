> 分两条主线回答：**① 长期记忆（MemoryStore）在哪些地方被调用；② InMemoryChatHistoryStore 的会话校验逻辑**。

## 一、长期记忆（MemoryStore）调用点

### 1.1 调用全景图

```
┌────────────────────────────────────────────────────────────────┐
│                      MemoryStore 调用点                         │
├────────────────────────────────────────────────────────────────┤
│ 【写入路径】                                                    │
│   AiAgentRunner.run()                                          │
│     └─ memoryExtractor.extract(userId, turn)  [异步]           │
│           └─ MemoryExtractor.saveOne()                          │
│                 ├─ memoryStore.findByUserAndContentLike()  ← 去重│
│                 └─ memoryStore.save()                       ← 保存│
├────────────────────────────────────────────────────────────────┤
│ 【读取路径】                                                    │
│   AiAgentRunner.run()                                          │
│     └─ memoryStore.searchByUser(userId, qVec, 5)  ← 向量召回   │
├────────────────────────────────────────────────────────────────┤
│ 【维护路径】                                                    │
│   MemoryDecayJob.decay()  [每日 3:00]                          │
│     ├─ memoryStore.getAllActiveUsers()                          │
│     ├─ memoryStore.decayAll(userId, 0.95)                      │
│     └─ memoryStore.deleteBelow(userId, 0.1)                    │
└────────────────────────────────────────────────────────────────┘
```

### 1.2 调用点 1：向量召回（读）

**位置**：`AiAgentRunner.run()`

```java
// 长期记忆召回：用本轮问题做向量检索，把召回结果拼进系统上下文。
List<Double> qVec = embeddingClient.embed(request.message());       // ← 向量化
List<MemoryItem> memories = memoryStore.searchByUser(userId, qVec, 5); // ← KNN 召回 top5
String memoryBlock = memories.stream()
        .map(m -> "- " + m.content())
        .collect(Collectors.joining("\n"));
```

**调用链**：

```
AiAgentRunner.run()
  └─ memoryStore.searchByUser(userId, qVec, 5)
        └─ RedisMemoryStore.searchByUser()
              └─ RediSearch KNN: (@userId:{xxx} @invalid:{0})=>[KNN 5 @embedding $vec]
```

**关键点**：

- ✅ **已调用**：每轮对话都会召回一次
- ⚠️ **无降级**：`embeddingClient.embed` 抛异常会中断主流程（新发现隐患 N-1）
- ⚠️ **召回结果拼进 memoryBlock**，由 `ContextBuilder.build` 注入系统消息

### 1.3 调用点 2：去重检查（写前）

**位置**：`MemoryExtractor.saveOne()`

```java
List<MemoryItem> existing = memoryStore.findByUserAndContentLike(userId, content);
if (existing != null && !existing.isEmpty()) {
    memoryStore.invalidate(existing.get(0).id());   // ← 旧记忆失效
}
```

**调用链**：

```
AiAgentRunner.run()
  └─ memoryExtractor.extract(userId, turn)  [@Async("memoryExecutor")]
        └─ MemoryExtractor.saveOne(userId, it)
              └─ memoryStore.findByUserAndContentLike(userId, content)
                    └─ RedisMemoryStore.findByUserAndContentLike()
                          ├─ stringRedisTemplate.opsForSet().members("ai:memory:user:{userId}")
                          └─ 遍历 id，readHashNative(key)，过滤 content.contains(keyword)
```

**关键点**：

- ✅ **已调用**：抽取记忆前做去重
- ⚠️ **性能问题**：遍历用户所有记忆 ID，逐条读取 Hash（K-9 相关）

### 1.4 调用点 3：保存记忆（写）

**位置**：`MemoryExtractor.saveOne()`

```java
List<Double> embedding;
try {
    embedding = embeddingClient.embed(content);   // ← 向量化
} catch (Exception e) {
    log.warn(">>> 记忆 embedding 失败，跳过保存：content={}, err={}", content, e.toString());
    return;
}
if (embedding == null || embedding.isEmpty()) {
    log.warn(">>> 记忆 embedding 为空，跳过保存：content={}", content);
    return;
}

memoryStore.save(MemoryItem.of(userId, type, content, embedding, importance));  // ← 保存
```

**调用链**：

```
MemoryExtractor.saveOne()
  └─ memoryStore.save(MemoryItem.of(...))
        └─ RedisMemoryStore.save()
              ├─ 原生 Lettuce HSET（主数据）
              │     └─ EXPIRE 90 天
              └─ StringRedisTemplate
                    ├─ SADD ai:memory:user:{userId} {memoryId}
                    └─ SET  ai:memory:reverse:{memoryId} {userId}
```

**关键点**：

- ✅ **已调用**：每条抽取的记忆都会保存
- ✅ **降级**：embedding 失败则跳过该条（不影响其他条目）
- ⚠️ **主数据失败仍写索引**：`save` 中主数据失败 `return`，但索引可能已写（K-14）

### 1.5 调用点 4：失效旧记忆（写）

**位置**：`MemoryExtractor.saveOne()`

```java
memoryStore.invalidate(existing.get(0).id());
```

**调用链**：

```
MemoryExtractor.saveOne()
  └─ memoryStore.invalidate(memoryId)
        └─ RedisMemoryStore.invalidate()
              ├─ GET ai:memory:reverse:{memoryId}  → userId
              └─ HSET ai:memory:{userId}:{memoryId} invalid=1 updatedAt=now
```

**关键点**：

- ✅ **已调用**：去重时旧记忆标记 `invalid=1`
- ⚠️ **非物理删除**：查询时靠 `@invalid:{0}` 过滤

### 1.6 调用点 5：批量衰减（维护）

**位置**：`MemoryDecayJob.decay()`（每日 3:00）

```java
@Scheduled(cron = "0 0 3 * * ?")
public void decay() {
    Set<String> activeUsers = memoryStore.getAllActiveUsers();     // ← 批量查询
    for (String userId : activeUsers) {
        memoryStore.decayAll(userId, 0.95);                        // ← 衰减
        memoryStore.deleteBelow(userId, 0.1);                      // ← 清理
    }
}
```

**调用链**：

```
MemoryDecayJob.decay()
  ├─ memoryStore.getAllActiveUsers()
  │     └─ RedisMemoryStore.getAllActiveUsers()
  │           └─ SCAN ai:memory:user:*
  ├─ memoryStore.decayAll(userId, 0.95)
  │     └─ 遍历 id，HSET importance=importance*0.95
  └─ memoryStore.deleteBelow(userId, 0.1)
        └─ 遍历 id，importance < 0.1 则 DEL
```

**关键点**：

- ✅ **已调用**：定时任务
- ⚠️ **兜底**：`MemoryStore.getAllActiveUsers` 接口 default 抛异常，但 Redis 实现已覆盖
- ⚠️ **性能**：SCAN 全量 + 逐条 HSET（K-7/K-8/K-9）

### 1.7 MemoryStore 调用点汇总表

| 方法                         | 调用者                       | 时机      | 频率      |
| -------------------------- | ------------------------- | ------- | ------- |
| `searchByUser`             | `AiAgentRunner`           | 每轮对话    | 每轮 1 次  |
| `findByUserAndContentLike` | `MemoryExtractor.saveOne` | 抽取记忆时   | 每条 1 次  |
| `save`                     | `MemoryExtractor.saveOne` | 抽取记忆时   | 每条 1 次  |
| `invalidate`               | `MemoryExtractor.saveOne` | 去重时     | 命中时 1 次 |
| `getAllActiveUsers`        | `MemoryDecayJob`          | 每日 3:00 | 每天 1 次  |
| `decayAll`                 | `MemoryDecayJob`          | 每日 3:00 | 每用户 1 次 |
| `deleteBelow`              | `MemoryDecayJob`          | 每日 3:00 | 每用户 1 次 |

**未调用**：

- `MemoryStore` 接口的 `default getAllActiveUsers`（被 Redis 实现覆盖）

## 二、InMemoryChatHistoryStore 会话校验

### 2.1 会话校验全景图

```
┌────────────────────────────────────────────────────────────────┐
│                  ChatHistoryStore 会话校验点                     │
├────────────────────────────────────────────────────────────────┤
│ 【调用入口】                                                    │
│   AiAgentService.chat()                                        │
│     ├─ history.exists(sessionId)          ← 判断新会话         │
│     └─ history.assertOwner(sessionId, userId)  ← 校验归属      │
├────────────────────────────────────────────────────────────────┤
│ 【加载会话】                                                    │
│   ContextBuilder.build()                                       │
│     └─ history.load(sessionId)            ← 加载历史消息        │
├────────────────────────────────────────────────────────────────┤
│ 【消息落库】                                                    │
│   AiAgentRunner.run()                                          │
│     └─ history.appendUser(...)            ← 落库 user           │
│   AgentLoop.run()                                              │
│     └─ history.appendAssistant(...)       ← 落库 assistant      │
├────────────────────────────────────────────────────────────────┤
│ 【辅助读取】                                                    │
│   AiAgentRunner.run()                                          │
│     └─ history.loadAssistant(...)         ← 读 assistant 内容   │
├────────────────────────────────────────────────────────────────┤
│ 【会话列表】                                                    │
│   Controller（未在本次代码中）                                   │
│     └─ history.sessions(currentUserId)    ← 用户会话列表        │
└────────────────────────────────────────────────────────────────┘
```

### 2.2 会话校验点 1：`exists(sessionId)`

**位置**：`AiAgentService.chat()`

```java
boolean newSession = !history.exists(sessionId);
if (!newSession) history.assertOwner(sessionId, userId);
```

**调用链**：

```
AiAgentService.chat()
  └─ history.exists(sessionId)
        └─ InMemoryChatHistoryStore.exists()
              └─ sessions.containsKey(sessionId)
```

**InMemory 实现**：

```java
private final Map<String, SessionMeta> sessions = new ConcurrentHashMap<>();

@Override
public boolean exists(String sessionId) {
    return sessions.containsKey(sessionId);   // ← 仅检查 key 存在
}
```

**关键点**：

- ✅ **已调用**：判断是否新会话
- ⚠️ **不校验 owner**：仅检查存在性，owner 由 `assertOwner` 单独校验

### 2.3 会话校验点 2：`assertOwner(sessionId, userId)`

**位置**：`AiAgentService.chat()`

```java
if (!newSession) history.assertOwner(sessionId, userId);
```

**调用链**：

```
AiAgentService.chat()
  └─ history.assertOwner(sessionId, userId)
        └─ InMemoryChatHistoryStore.assertOwner()
              └─ 校验 meta.owner().equals(userId)
```

**InMemory 实现**：

```java
private record SessionMeta(String owner, String title,
                           LocalDateTime createdAt, LocalDateTime updatedAt) {}

@Override
public void assertOwner(String sessionId, String userId) {
    SessionMeta meta = sessions.get(sessionId);
    if (meta != null && !meta.owner().equals(userId)) {
        throw new IllegalStateException("会话不属于当前用户");   // ← 抛异常
    }
}
```

**关键点**：

- ✅ **已调用**：非新会话时校验
- ⚠️ **仅抛异常**：`AiAgentService.chat` 中未单独 catch，会被外层 `catch (Exception e)` 捕获，返回"系统繁忙"错误 SSE
- ⚠️ **`meta == null` 时不抛异常**：如果 sessionId 在 `sessions` 中被并发删除，`assertOwner` 会静默通过

### 2.4 会话校验点 3：`load(sessionId)`

**位置**：`ContextBuilder.build()`

```java
public List<Message> build(String sessionId, String newUserMsg, String longTermMemoryBlock) {
    List<Message> stored = history.load(sessionId);   // ← 加载历史
    List<Message> systemMsgs = stored.stream().filter(Message::isSystem).toList();
    List<Message> dialog = stored.stream().filter(m -> !m.isSystem()).toList();
    // ...
}
```

**InMemory 实现**：

```java
@Override
public List<Message> load(String sessionId) {
    return messages.values().stream()                       // ← 全量扫描所有消息
            .filter(m -> sessionId.equals(m.sessionId()))   // ← 按 sessionId 过滤
            .sorted(Comparator.comparingLong(StoredMessage::id))
            .map(this::toMessage)
            .toList();
}
```

**关键点**：

- ✅ **已调用**：每轮对话构建上下文时
- ⚠️ **不校验 owner**：仅按 sessionId 过滤
- ⚠️ **性能问题**：`messages.values().stream()` 全量扫描，消息多时 O(N)

### 2.5 会话校验点 4：`appendUser` / `appendAssistant`

**位置**：

- `AiAgentRunner.run()` → `history.appendUser(...)`
- `AgentLoop.run()` → `history.appendAssistant(...)`

**InMemory 实现**：

```java
@Override
public void appendUser(long userMessageId, String sessionId, String userId, String message) {
    append(sessionId, userId, userMessageId, "USER", message, null);
}

@Override
public void appendAssistant(long assistantMessageId, String sessionId, String content) {
    SessionMeta meta = sessions.get(sessionId);
    append(sessionId, meta == null ? "" : meta.owner(), assistantMessageId, "ASSISTANT", content, null);
}

@Override
public void append(String sessionId, String userId, long messageId,
                   String role, String content, String extra) {
    LocalDateTime now = LocalDateTime.now();
    sessions.compute(sessionId, (k, old) -> new SessionMeta(
            old != null ? old.owner() : userId,             // ← 首次写入设置 owner
            old != null && old.title() != null && !old.title().isBlank()
                    ? old.title() : firstLine(content),     // ← 首次写入设置 title
            old != null ? old.createdAt() : now,
            now));
    messages.put(messageId, new StoredMessage(messageId, sessionId, userId, role, content, extra));
}
```

**关键点**：

- ✅ **已调用**：写入时
- ⚠️ **`appendAssistant` 依赖 `sessions.get(sessionId)`**：若 sessionId 不存在（异常场景），owner 会是空字符串 `""`
- ⚠️ **owner 只在首次写入时设置**：后续 `append` 不会更新 owner

### 2.6 会话校验点 5：`loadAssistant(assistantMessageId)`

**位置**：`AiAgentRunner.run()`

```java
List<Message> turn = List.of(
        Message.user(request.message()),
        Message.assistant(history.loadAssistant(assistantMessageId))   // ← 读取 assistant 内容
);
memoryExtractor.extract(userId, turn);
```

**InMemory 实现**：

```java
@Override
public String loadAssistant(long assistantMessageId) {
    StoredMessage message = messages.get(assistantMessageId);
    if (message == null || !"ASSISTANT".equalsIgnoreCase(message.role())) return "";
    return message.content() == null ? "" : message.content();
}
```

**关键点**：

- ✅ **已调用**：记忆抽取前读取
- ⚠️ **不校验 owner**：仅按 messageId 读取
- ⚠️ **不校验 sessionId**：跨会话可能读到消息

### 2.7 会话校验点 6：`sessions(currentUserId)`

**位置**：Controller（未在本次代码中，但接口定义了）

**InMemory 实现**：

```java
@Override
public List<AiChatSessionResponse> sessions(String currentUserId) {
    List<AiChatSessionResponse> result = new ArrayList<>();
    sessions.forEach((sessionId, meta) -> {
        if (!meta.owner().equals(currentUserId)) return;   // ← 按 owner 过滤
        AiChatSessionResponse item = new AiChatSessionResponse();
        item.setSessionId(sessionId);
        item.setTitle(meta.title());
        item.setCreatedAt(meta.createdAt());
        item.setUpdatedAt(meta.updatedAt());
        result.add(item);
    });
    result.sort(Comparator.comparing(AiChatSessionResponse::getUpdatedAt,
            Comparator.nullsLast(Comparator.reverseOrder())));
    return result;
}
```

**关键点**：

- ✅ **已调用**：Controller 查询用户会话列表
- ✅ **按 owner 过滤**：只返回当前用户的会话

### 2.8 会话校验点汇总表

| 方法                | 调用者                    | 是否校验 owner | 校验方式                          |
| ----------------- | ---------------------- | ---------- | ----------------------------- |
| `exists`          | `AiAgentService.chat`  | ❌          | 仅检查 key 存在                    |
| `assertOwner`     | `AiAgentService.chat`  | ✅          | `meta.owner().equals(userId)` |
| `load`            | `ContextBuilder.build` | ❌          | 仅按 sessionId 过滤               |
| `appendUser`      | `AiAgentRunner.run`    | ❌          | 首次写入设置 owner                  |
| `appendAssistant` | `AgentLoop.run`        | ❌          | 依赖 `sessions.get(sessionId)`  |
| `loadAssistant`   | `AiAgentRunner.run`    | ❌          | 仅按 messageId                  |
| `sessions`        | Controller             | ✅          | 按 owner 过滤                    |

## 三、会话校验完整性分析

### 3.1 校验链路时序

```
用户请求（sessionId, userId）
   │
   ▼
┌─────────────────────────────────────────────────────────────┐
│ AiAgentService.chat()                                       │
│                                                             │
│ 1. newSession = !history.exists(sessionId)                  │
│    ├─ true  → 新会话，跳过 owner 校验                        │
│    └─ false → 老会话，走 2                                   │
│                                                             │
│ 2. history.assertOwner(sessionId, userId)                   │
│    ├─ meta == null        → 静默通过 ⚠️                      │
│    ├─ meta.owner == userId → 通过 ✅                         │
│    └─ meta.owner != userId → 抛 IllegalStateException ❌     │
│                                                             │
│ 3. AiToolContext.capture(userId, redisUtils)                │
│ 4. chatExecutor.execute(() -> runner.run(...))              │
└─────────────────────────────────────────────────────────────┘
   │
   ▼
┌─────────────────────────────────────────────────────────────┐
│ AiAgentRunner.run()                                         │
│   ├─ history.appendUser(userMessageId, sessionId, userId, ...) │
│   │    └─ append() → sessions.compute() 首次写入设置 owner    │
│   │                                                          │
│   ├─ contextBuilder.build(sessionId, ...)                   │
│   │    └─ history.load(sessionId)  ← 无 owner 校验 ⚠️         │
│   │                                                          │
│   └─ history.loadAssistant(assistantMessageId)  ← 无校验 ⚠️   │
└─────────────────────────────────────────────────────────────┘
   │
   ▼
┌─────────────────────────────────────────────────────────────┐
│ AgentLoop.run()                                             │
│   └─ history.appendAssistant(assistantMessageId, sessionId, content) │
│        └─ append() → 依赖 meta.owner()，可能为空 ⚠️           │
└─────────────────────────────────────────────────────────────┘
```

### 3.2 校验缺口

| 缺口                                         | 位置                         | 风险                                                                  |
| ------------------------------------------ | -------------------------- | ------------------------------------------------------------------- |
| **G1**：`exists` 不校验 owner                  | `AiAgentService.chat`      | 若 sessionId 属于他人，`exists` 返回 true，但 `assertOwner` 会拦（靠 assertOwner） |
| **G2**：`assertOwner` 中 `meta == null` 静默通过 | `InMemoryChatHistoryStore` | 并发删除时可能越权                                                           |
| **G3**：`load` 不校验 owner                    | `ContextBuilder.build`     | 若 sessionId 被篡改，可读到他人会话                                             |
| **G4**：`loadAssistant` 不校验 owner           | `AiAgentRunner.run`        | 按 messageId 可跨会话读取                                                  |
| **G5**：`appendAssistant` 依赖 `sessions.get` | `AgentLoop.run`            | 若 sessionId 不存在，owner 为空                                            |
| **G6**：无并发 owner 校验                        | `append`                   | 首次写入设置 owner，后续不更新                                                  |

### 3.3 攻击场景推演

**场景 1：sessionId 篡改**

```
攻击者：userId = "attacker"，sessionId = "victim-session"
   │
   ▼
AiAgentService.chat()
  ├─ newSession = !history.exists("victim-session") = false
  ├─ history.assertOwner("victim-session", "attacker")
  │     └─ meta.owner() = "victim" != "attacker"
  │     └─ 抛 IllegalStateException ✅ 拦截
  └─ 返回错误 SSE
```

**结论**：✅ 已拦截（靠 `assertOwner`）

**场景 2：sessionId 并发删除后篡改**

```
T1: 攻击者请求 sessionId="victim-session"
T2: 同时受害者删除会话
T3: assertOwner 中 meta == null → 静默通过 ⚠️
T4: 攻击者可以继续操作
```

**结论**：⚠️ 存在竞态窗口（G2）

**场景 3：messageId 猜测**

```
攻击者：assistantMessageId = 100
   │
   ▼
history.loadAssistant(100)
  └─ messages.get(100) → 返回他人 assistant 内容 ⚠️
```

**结论**：⚠️ 无 owner 校验（G4），但 `assistantMessageId` 由服务端分配，攻击者难以猜测

## 四、总结

### 4.1 长期记忆调用总结

| 维度        | 结论                                                                     |
| --------- | ---------------------------------------------------------------------- |
| **是否有调用** | ✅ 有，共 7 个调用点                                                           |
| **读路径**   | `AiAgentRunner` → `searchByUser`（每轮对话）                                 |
| **写路径**   | `MemoryExtractor` → `save` / `invalidate` / `findByUserAndContentLike` |
| **维护路径**  | `MemoryDecayJob` → `getAllActiveUsers` / `decayAll` / `deleteBelow`    |
| **降级机制**  | ✅ embedding 失败跳过该条；❌ 召回失败未降级（N-1）                                      |
| **性能隐患**  | 全量 SCAN、逐条 HSET、遍历读取（K-7/K-8/K-9）                                      |

### 4.2 会话校验总结

| 维度        | 结论                                                          |
| --------- | ----------------------------------------------------------- |
| **是否有校验** | ✅ 有，但**不完整**                                                |
| **入口校验**  | `AiAgentService.chat` → `exists` + `assertOwner`            |
| **加载校验**  | ❌ `load` / `loadAssistant` 无 owner 校验                       |
| **写入校验**  | ❌ `append` 首次设置 owner，后续不校验                                 |
| **列表校验**  | ✅ `sessions` 按 owner 过滤                                     |
| **主要缺口**  | G2（assertOwner 静默通过）、G3（load 无校验）、G4（loadAssistant 无校验）     |
| **可接受**   | 入口校验（assertOwner）挡住了主要攻击面；内部方法依赖 sessionId/messageId 的不可猜测性 |

### 4.3 建议修复

| 编号  | 修复                                  | 优先级  |
| --- | ----------------------------------- | ---- |
| G2  | `assertOwner` 中 `meta == null` 时抛异常 | 🟡 中 |
| G3  | `load` 增加 userId 参数校验               | 🟡 中 |
| G4  | `loadAssistant` 增加 userId 参数校验      | 🟡 中 |
| G5  | `appendAssistant` 校验 `meta != null` | 🟢 低 |
| N-1 | `AiAgentRunner` 中 embed 异常降级        | 🔴 高 |

**一句话**：

- **长期记忆**：✅ 已完整调用（读/写/维护），但**召回失败未降级**是隐患；
- **会话校验**：✅ 入口有 `assertOwner`，但**内部加载方法（load/loadAssistant）无 owner 校验**，存在越权读的潜在风险，靠 sessionId/messageId 不可猜测性兜底。
